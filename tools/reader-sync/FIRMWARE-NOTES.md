# Firmware: sync-on-wake

Device-side half of the dashboard. When enabled, the reader connects to WiFi at boot,
reads the manifest from the Mac dashboard, downloads new books to the SD card and a new
home-screen image to the sleep screen, then turns WiFi off and continues booting.

> ⚠️ **Not yet compiled or device-tested.** This was written against the codebase
> conventions but `pio` was not available in the authoring environment. Build with
> `pio run` and test on hardware before relying on it. Open items are listed at the end.

## Files changed

New:
- `src/network/LibrarySync.{h,cpp}` — the engine: headless WiFi connect → fetch manifest →
  download new books (`HttpDownloader::downloadToFile` + `clearBookCache`) → install home
  image (`installSleepImage` + set sleep mode `CUSTOM`) → tear WiFi down. Best-effort; all
  failures are logged and swallowed so boot always continues.
- `src/SyncStateStore.{h,cpp}` — a `PersistableStore` at `/.crosspoint/sync.json` tracking
  which book hashes have been downloaded and the last home-image hash, so nothing is
  re-downloaded. The book-hash vector is freed (`releaseMemory()`) right after the boot sync
  so it does not stay resident during reading.

Edited:
- `src/CrossPointSettings.h` — `syncOnWake`, `syncOnlyWhenCharging`, `syncServerUrl[128]`.
- `src/JsonSettingsIO.cpp` — persist `syncServerUrl` (like `sdFontFamilyName`).
- `src/SettingsList.h` — two on-device toggles (System tab) + a web-configured URL entry.
- `src/main.cpp` — the gated call in `setup()`.
- `lib/I18n/translations/english.yaml` — 5 new strings (regenerated by the build).

PlatformIO auto-globs `src/**/*.cpp`, so the new modules need no build-file change.

## Build

```bash
pio run          # regenerates I18n headers and compiles
```

## Configure

1. **Enable it:** Settings → System → **Sync books on wake** (and, if you want it to run on
   battery too, turn off **Sync only when charging** — it defaults on).
2. **Set the server address:** the dashboard prints e.g. `http://192.168.1.50:8765`. Enter that
   as **Library Sync Server URL** on the reader's **web** Settings page (open the wireless-
   transfer screen, browse to the reader, Settings). It's web-only on purpose — typing a URL
   with the buttons is painful. (The value is the `syncServerUrl` key in `/api/settings`.)

## How it runs

In `setup()`, after the display is up and the boot target is routed, on a **full (splash)
boot** only, if `syncOnWake` is on, a URL is set, and (by default) USB power is present:
`LibrarySync::runAtBoot(renderer)` draws "Syncing your library…", does the sync, then the
routed activity (usually Home) paints. Quick-resume / silent wakes are never delayed.

## Device-test checklist

- [ ] Compiles clean (`pio run`), no warnings.
- [ ] Toggles appear under Settings → System and persist across reboot.
- [ ] URL is settable on the web Settings page and persists (`/.crosspoint/settings.json`).
- [ ] With the dashboard running and a book staged: reboot while on USB → "Syncing…" shows,
      book lands on the SD, appears under **Browse Files**.
- [ ] Staged home image becomes the sleep screen after a sync.
- [ ] Reboot again with nothing new staged → no re-download (hash tracking works).
- [ ] Dashboard off / wrong URL / no WiFi → boot still completes quickly, no hang.
- [ ] Heap after a sync is healthy (`ESP.getFreeHeap()`).

## Known limitations / things to verify

- **Watchdog:** `runAtBoot` blocks in `setup()`. WiFi wait and download callbacks feed the
  task WDT (`esp_task_wdt_reset`), but the manifest `fetchUrl` is a single blocking call with
  no callback. If a slow/hanging fetch trips the WDT on device, either wrap the call with
  `esp_task_wdt_delete(NULL)` for its duration, or move the whole flow into a `SyncActivity`
  (model on `ClockSyncActivity`) that runs in the loop instead of `setup()`.
- **Home vs. recents:** a synced book shows under Browse Files immediately, but only appears
  on the Home "Continue/Recent" list after it's opened once (Home reads `RecentBooksStore`,
  not a directory scan).
- **Triggers on splash boots only, USB by default.** Deep-sleep wakes that quick-resume won't
  sync. Tune the gate in `main.cpp` if you want broader triggering.
- **Manifest is buffered + parsed in RAM.** Fine for a normal library; a huge staging folder
  would pressure the 380 KB heap. Could switch to streaming parse later.
- **Discovery is manual (IP/URL).** DHCP can change the Mac's IP — set a reservation, or add
  mDNS discovery later.
